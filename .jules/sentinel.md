## 2026-07-13 - [Broken Authentication and Object Level Authorization in Chat History & Task Endpoints]
**Vulnerability:** The `/api/history` and `/api/memory` endpoints were exposed publicly without `authMiddleware` verification, trusting client-provided `uid` parameters. Additionally, `/api/tasks/pending` used `MemoryService.getPendingTasks()`, which returned all pending tasks across all users regardless of who made the request, leading to potential leak of sensitive execution tasks and commands.
**Learning:** These endpoints were initially created without standard middleware protection, possibly during debugging or early development, or were overlooked when building out the mobile/desktop integration, assuming that clients wouldn't attempt to exploit queries with other user IDs.
**Prevention:** Always secure user-specific data-access endpoints with explicit authentication middleware. Use the verified, token-derived `req.user.uid` rather than trusting user-provided query parameters. Enforce strict authorization checks inside the underlying database query filters.
